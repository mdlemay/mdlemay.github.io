= Michael LeMay

Personal site for https://m.lemays.org/[m.lemays.org], built with https://jekyllrb.com/[Jekyll] and https://asciidoctor.org/[AsciiDoc] and hosted on GitHub Pages.

== Local preview

----
bundle install
bundle exec jekyll serve
----

Then open http://127.0.0.1:4000/.

== Publishing

GitHub Pages cannot run `jekyll-asciidoc` with its built-in Jekyll builder, so this repository uses a GitHub Actions workflow to build and deploy.

In the repository settings, set *Pages → Source* to *GitHub Actions*.
After the first successful workflow run, point the `m.lemays.org` DNS records at GitHub Pages if they still target the previous host.

== Monthly patent scan

A scheduled workflow searches the USPTO Open Data Portal Patent File Wrapper API for new US patents and published applications that list Michael LeMay as an inventor and Intel as the applicant or assignee. If it finds listings that are not already on `patents.adoc`, it opens a pull request. When a newly granted patent is the first issuance of a currently listed application, that application row is removed.

. Sign in to the https://data.uspto.gov/[USPTO Open Data Portal] with a USPTO.gov account that has multi-factor authentication enabled
. Create an API key on the https://data.uspto.gov/apikey[Manage API Key] page
. Add it as the repository secret `USPTO_ODP_API_KEY`
. In https://github.com/mdlemay/mdlemay.github.io/settings[Settings → General], under *Features*, enable *Issues* and *Pull requests*
. In https://github.com/mdlemay/mdlemay.github.io/settings/actions[Settings → Actions → General], under *Workflow permissions*, enable *Allow GitHub Actions to create and approve pull requests*
. The workflow runs on the 1st of each month and can also be started from the *Actions* tab

To run locally, install the dependencies with `pip install -r .github/scripts/requirements.txt` and set `USPTO_ODP_API_KEY`.
Run the scanner with `python .github/scripts/sync_patents.py`.
To compare the broad and narrowed server-side filters without changing `patents.adoc`, run `python .github/scripts/diagnose_patents.py`. The same diagnostic is available when manually starting the workflow from the *Actions* tab.

=== Adapting the scanner

Copy `.github/scripts/` and `.github/workflows/scan-patents.yml` into the other repository. The scripts are MIT-licensed and cover US utility applications. Edit the settings at the top of `patents_common.py`: `INVENTOR_FIRST_NAME`, `INVENTOR_LAST_NAMES`, `ORGANIZATION_NAME`, `USER_AGENT`, `PATENTS_PATH`, the two section headings, and `ISSUED_KIND_CODE`. The USPTO queries and the record checks are built from those settings. Leave `ORGANIZATION_NAME` empty to keep every utility filing for the inventor. The first spelling in `INVENTOR_LAST_NAMES` is the structured query; add further spellings when the USPTO index uses more than one form of that name.

The patents page needs `ISSUED_HEADING` followed later by `APPLICATIONS_HEADING`. Issued and application rows are AsciiDoc list items in this form:

----
. https://patents.google.com/patent/US12754853B2/en[12,754,853 (2026): Title]
. https://patents.google.com/patent/US20250284832A1/en[18/946,869: TITLE]
----

Text after the application list stays where it is. Set `add-paths` in `scan-patents.yml` to the same path as `PATENTS_PATH`. Add the `USPTO_ODP_API_KEY` secret and allow GitHub Actions to open pull requests, as described above. The workflow commits that page on `bot/patents-update` at 16:00 UTC on the first day of each month.

== Editing content

* Pages live at the repository root as `.adoc` files.
* Papers are in `_publications/`.
* Posts are in `_posts/`. Tag a post `personal` or `professional` to include it in that category feed.
* Talks are in `_talks/`.
* Projects are in `_projects/`.
